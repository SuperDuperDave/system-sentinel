# Measuring saved Stack cost

Run `py -3 scripts\measure_stack.py` from a Windows checkout, or `PYTHONPATH=. python scripts/measure_stack.py` on Linux/WSL. The script builds one, three and ten synthetic 2,000-row Record items in a disposable directory. It reports stored JSON bytes and median times over five warm reads or edits for the compact index, one exact item, a metadata edit and a prompt choice, plus one add. The directory is removed when the script finishes. It never opens the installed Stack or takes a machine reading.

These are direct `Stack` storage operations. They exclude HTTP/MCP serialization, redaction, composition, capture compression, client rendering and concurrent lock waits; they do not control for antivirus scanning. The add case uses whole readings without selected record ids, so it does not measure duplicate checks that scan a stored selection's records. The ten-item case deliberately stresses a large investigation; it is not a claim about how many items people save. Results describe the system temporary directory on the named platform, which may be a different filesystem from the installed Stack. Measure normal use and concurrent requests separately before changing the storage format.

The current `stack.json` is one atomically replaced document. It keeps full readings and supports exact item retrieval, capture and composition; routine list answers return compact provenance. A new storage format would need to preserve those behaviors, refuse malformed old data without overwriting it, and prevent an older executable from silently creating a divergent empty Stack after an upgrade.
