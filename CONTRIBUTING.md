# Contributing

System Sentinel is worked by a person and an agent together, by a working method kept in a private repository beside the tool. The part of it a contributor needs is here:

- **One boundary.** Nothing reads the machine except through a reading registered in `sentinel/reading.py`'s catalog and taken through `sentinel/bridge.py`. A new capability is a new reading, and it becomes a route, an OpenAPI entry and an MCP tool by being registered. [docs/API.md](docs/API.md) is the contract; change it in the same change.
- **Evidence, not verdicts.** A reading's outcome says whether the machine was observed. Sections are `raw`, `derived`, `invariant` or `inferred`, and an inferred section carries its basis. Nothing in the tool diagnoses; it shows leads.
- **Nothing private on the wire by default.** Serial numbers, the computer name, user names, MAC addresses and profile paths are removed by `sentinel/redact.py`. If a new reading carries something of that kind, declare it in the reading's `private` list and make sure the policy removes it; add a rule to the policy, not to the reading.
- **Verify on the machine.** `./.venv/bin/python -m pytest` runs the unit tests through a fake bridge and the host tests against the real Windows event log where there is one. A reading is done when it has run on a real machine and its envelope was inspected, including the failure path. `npm run build` in `dashboard/` type-checks and builds the dashboard; check a view on glass at phone width (390) and desktop (1440) before calling it done. GitHub Actions runs the same commands on every push, the host tests included, on a Windows machine that is not the one this was built for; [Verification](#verification) below says what a green run establishes and what it does not.
- **The identity is owned.** Colors, faces and the mark come from [docs/design/IDENTITY-DIRECTIONS-2026-09-20.md](docs/design/IDENTITY-DIRECTIONS-2026-09-20.md); the phosphor is light only, never text.

Pull requests are welcome. Say what was checked and how: source inspected, run locally, tested, and observed on a host are four different claims.

## Verification

From the root, `./.venv/bin/python -m pytest` runs the suite in `tests/`: unit tests through a fake bridge, and tests marked `host` that read the real Windows event log through `powershell.exe` (skipped where there is no bridge; `-m "not host"` deselects them). From `dashboard/`, `npm run build` type-checks and builds the dashboard into `sentinel/static`. The server runs with `./.venv/bin/python -m sentinel serve` (or the installed `system-sentinel serve`), and every reading is exercised by taking it through its route or MCP tool and reading the envelope. A passing suite establishes what the fake bridge and this machine returned today; a build establishes that it built. Neither establishes the reading a person or an agent will make from it: check a view on glass at phone and desktop width before calling it done.

Every push is checked again away from this machine. [`.github/workflows/ci.yml`](.github/workflows/ci.yml) takes the unit suite and the dashboard build on Linux, and on a Windows runner it installs the package, runs the suite with the host tests included — all of it but `tests/test_bridge.py`, whose fake `powershell.exe` is a script only Linux can execute — takes the health reading with `system-sentinel check` and builds the executable with `build\windows\build.ps1`, keeping it as a workflow artifact. That runner is the thing this project otherwise has none of: a Windows machine nobody here tuned, with its own event log, its own parts and its own noise. A green run establishes what that runner returned on that commit — not what this machine returns, and not the reading a person or an agent will make from either. [`.github/workflows/release.yml`](.github/workflows/release.yml) builds from a tag, refuses a tag that does not name `sentinel.__version__`, writes the checksum, attests where the file came from, and leaves a draft release, which is published once its assets have been checked against the list and its attestation verified.
